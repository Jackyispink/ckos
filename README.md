# 企业诊断知识库

项目路径：`D:\yidui\env\ckos`。原始报告：`data`。Python：`D:\yidui\miniconda\envs\ckos\python.exe`（3.12）。

## 启动

工作台页面：`/knowledge` 为企业知识库，`/industry` 为行业研究页面。两者共享项目导航，根路径仍可打开知识库。前端继续由 FastAPI 统一提供，无需另外启动前端服务。

行业研究首版已接入 `/industry`：先填写行业、地区、历史与预测周期、研究目的和边界，系统生成十章研究问题及关键词计划。可按章节保存来源证据，再由后台逐章生成并最后生成摘要。项目、证据、章节和进度保存在 PostgreSQL。当前网页搜索供应商尚未配置，因此自动联网采集仍待接入；页面支持先人工补充证据，未配置 `LLM_API_KEY` 时生成任务会明确停在等待配置状态。

网页搜索采用适配器层，统一协议位于 `app/industry_research/search/base.py`，厂商选择由 `WEB_SEARCH_PROVIDER` 控制。首个适配器为 Exa；配置 `EXA_API_KEY` 后，可在章节中运行自动搜索。Exa 默认只对超时、连接失败、对端提前断开等尚未获得 HTTP 响应的瞬态传输错误额外重试 1 次；401/402/403、其他业务 4xx 和所有已收到的 HTTP 错误响应均不重试。短退避由 `EXA_RETRY_BASE_DELAY_SECONDS` 与 `EXA_RETRY_JITTER_SECONDS` 配置；考虑到超时请求仍可能已被服务端受理并计费，额外重试硬性封顶为 1 次，可设置 `EXA_TRANSPORT_MAX_RETRIES=0` 完全禁用。每个成功查询仍会立即去重并入库。以后接入其他厂商时新增适配器并注册到 `factory.py`，研究计划、证据库、报告生成和前端不需要感知厂商字段。

资料采集采用“AKShare优先、网页搜索补缺口”的低成本路由。AKShare固定为已验证的白名单接口，首批覆盖中国GDP、PPI、PMI和海关进出口，并预留上市公司财务指标；不允许模型根据网页或用户文字任意调用Python函数。第3章可用的宏观数据先写入统一证据库并缓存7天，再减少一次Exa查询；行业定义、政策、市场规模和竞争等非结构化问题继续由网页搜索完成。页面按钮“低成本采集本章资料”会展示两类数据分别保存了多少条及实际网页查询预算。

报告完成后页面切换为连续阅读式排版，并显示“下载完整Word报告”。导出的 `.docx` 包含编辑式封面、研究任务说明、目录、摘要、十章分页正文、资料来源及统一页眉页脚；只有十章与摘要全部完成的项目才允许下载。文件按项目编号缓存在 `storage/exports`，再次下载会以当前数据库内容重新生成。

在项目目录的 PowerShell 中运行 `./start.ps1`，然后访问 http://127.0.0.1:8000 。启动时增量入库，已处理且未变化的报告自动跳过。新增或修改报告后重新启动即可更新。

`start.ps1` 必须保持窗口打开，窗口会实时显示HTTP请求、行业资料采集、逐章生成和异常信息；同一份输出同时保存在 `storage/logs/时间.log`。如果当前终端是 CMD（提示符形如 `D:\...>`），请运行 `start-visible.cmd`，不要依赖 CMD 对 `.ps1` 文件的关联打开方式。停止服务使用 `Ctrl+C`。

依赖已在指定环境中可用。需要重建环境时运行：

```powershell
& 'D:\yidui\miniconda\envs\ckos\python.exe' -m pip install -r requirements.txt
```

## 大模型接口

已按用户提供的书生 ChatAPI 文档适配非流式 HTTP 调用。项目已创建 `.env`，填写 `LLM_API_KEY=你的个人token` 后重启服务即可。token 不需要包含 `Bearer` 前缀。默认地址为 `https://chat.intern-ai.org.cn/api/v1/chat/completions`，默认模型为已通过完整报告问答测试的 `intern-s1-mini`；可通过 `LLM_MODEL` 切换为账号有权限的模型。

`LLM_TIMEOUT=150` 是客户端等待时长，不能延长文档所述服务端 120 秒限制。`LLM_MAX_TOKENS=3000` 控制输出长度。`LLM_THINKING_MODE` 留空使用服务端默认，填写 `true`/`false` 时仅对文档指定的六种模型发送。token 过期、权限不足和限流会显示具体提示。输出截断不保存为完整答案。未配置 token 时仍可检索原文。

文档默认限制每用户每分钟 30 次调用：首问通常调用一次，追问通常调用两次（改写及作答），限流后请稍后重试。已完成真实模型连通测试。本地服务需要具备外网访问权限。

## PostgreSQL 数据库

运行时仅使用 PostgreSQL 17，数据库为 `ckos`，服务地址 `127.0.0.1:5432`。连接参数在 `.env` 中使用 `PGHOST`、`PGPORT`、`PGDATABASE`、`PGUSER`、`PGPASSWORD` 配置，也支持优先使用 `DATABASE_URL`。密码不写入代码或日志。数据库依赖本机已有的 Windows 服务 `postgresql-x64-17`，需要保持运行；`start.ps1` 启动应用并增量入库，不负责安装数据库服务。

2026-09-03 已迁移并逐表校验 85 份报告、1,659 个片段、1 个会话和 2 条消息。旧的 `storage/knowledge.sqlite3` 与迁移前快照均保留作为备份，应用不再读写它们。后续 PostgreSQL 新增记录不包含在这些历史备份中，应另行使用 `pg_dump` 备份 PostgreSQL。

迁移脚本：`python -m scripts.migrate_sqlite`（使用指定 Python 环境）。运行前先停止应用写入；脚本只允许目标四张表为空，会保留 SQLite 快照、在一个 PostgreSQL 事务中复制并校验全部字段、恢复消息自增序列。发现目标非空或校验不一致会中止，禁止覆盖现有数据。已迁移完成，不要重复执行。

SQLite 文件保存在项目目录；PostgreSQL 的物理数据由现有服务管理，目录为 `D:\yidui\postgresql\data`。原始 Word 报告仍在项目 `data` 目录。

## 上传前检查与报告更新

企业知识库的“批量上传”默认最多同时处理3份，可切换1/2/3份，选择文件后先自动识别企业名、报告名，全部完成后分组展示同名项并等待用户核对；确认后才查重入库。支持逐份修改名称和相似度阈值（试用默认90%，可调整50%～99.9%）。先检查同一企业下的报告名称，再比对原始正文、表格及图片/图表文件指纹，检查通过后才正式保存文件和切片入库。完全重复的内容始终拦截；高度相似时显示已有报告、相似度及部分文字差异。每份文件可选择快速检查（索引筛选候选）或严格检查（全库比较），快速检查存在近似筛选漏检风险。已有原文特征和固定权重保存在PostgreSQL，后续只增量更新。

确认入库后，浏览器立即取得后台任务编号并轮询状态。页面同时显示整批进度和每份报告的百分比、当前阶段；关闭页面不会中断已经提交的后台任务，但服务重启会清空任务状态。失败文件保留暂存件，修改名称或阈值后可以重试；成功文件不会重复提交。再次点击且没有待处理文件时，页面显示累计结果，不再误报“成功0份、未入库0份”。

每份入库报告使用独立文档编号；原文切片按文档编号隔离，结构化内容按报告编号隔离，企业归属使用企业编号，查重特征也按文档编号保存。指定报告问答只读取该报告的结构化块；问题中的企业与所选报告不一致时拒绝检索。自动化测试覆盖两家企业在切片、结构化内容、查重索引和指定报告检索中的互不混入。

选择同一企业的已有报告作为更新目标后，先查看差异并确认，再保存新版。旧版移入回收站，原件与历史回答保留，旧版人工编辑不自动复制。详细算法、版本恢复方式与已知边界见 [STRUCTURED_PIPELINE.md](STRUCTURED_PIPELINE.md)。

## 删除会话操作

左侧每条会话右侧有“删除”按钮，点击并确认后删除该会话及全部问答和引用记录，不影响报告或知识索引。删除当前会话后自动切换到其他会话；没有剩余会话时创建空会话。生成回答时暂时禁用删除按钮。删除无法在页面中撤销。

资料解析和索引均在本地运行；启用模型后，相关资料片段和有限的会话历史会发送到配置的 API。

## 问答和记忆

- 85 份 Word 报告按文档顺序提取正文和表格，切成约 1,200 字的片段。引用记录文件名、正文段落或表格行，可展开查看和下载原文件；不猜测 Word 页码。
- 使用中文分词和 BM25 检索，支持指定一份报告。当前没有接入向量模型，也不依赖外部向量库。
- 问题明确包含文件名中的企业名称时，先定位企业（兼容中英文括号）；单企业“诊断建议、总结”等整体问题，在全部片段文字不超过 40,000 字时提供完整已入库文本，避免固定前十条检索遗漏章节。超出范围或企业不明确时仍使用片段检索。此功能不包含图片 OCR。
- 回答支持标题、加粗、列表、表格和代码的安全排版，参考原文默认折叠。历史回答刷新后也使用新排版；新的检索策略需要重新提问才会生效。
- 每个会话独立保存于 PostgreSQL `ckos` 数据库，刷新网页或重启服务后保留。新会话不使用其他会话内容。
- 模型调用使用最近最多 12 条、合计最多 14,000 字历史消息；先把追问改写为独立问题，再重新检索，再生成带来源的答案。完整历史留在数据库中，超过窗口的早期细节不会自动进入模型；需要时请在问题中重述。
- 同一会话的请求串行处理，调用失败不写入半轮历史，可直接重试。当前以单进程启动。

## 使用范围

这是本机使用的首版，默认只监听 127.0.0.1，尚无多用户登录。资料中的图片、图表截图没有 OCR，不能回答只存在于图片中的内容。检索结果不等同于全量扫描，不支持可靠的“85 家总体排名/精确统计”；答案要求说明资料不足。删除源文件不会自动删除已有索引；如需同步删除，应先备份数据库后增加对应管理流程。

验证：`& 'D:\yidui\miniconda\envs\ckos\python.exe' -m pytest -q`。

数据库测试在 PostgreSQL 中创建随机命名的隔离 schema，测试后清理，不修改业务表。测试账号需要创建 schema 的权限。

当前 `.env` 使用 `intern-s1-mini` 和 `LLM_THINKING_MODE=false`，降低长时间推理带来的等待。完整报告直接调用测试约 11 秒返回，耗时随模型服务负载变化。客户端等待仍为 150 秒，不会自动重试计费请求；失败本轮不保存。

## 制造业报告的自动研究增强

制造业模板不要求用户先填写市场、客户、设备或财务表格。点击“生成十章与摘要”后，系统按以下顺序自动执行：

1. 优先读取 AKShare 与本地缓存，再使用已配置的网页搜索补足资料缺口。
2. 从可用证据中抽取带原文、来源、日期和证据编号的结构化候选记录；同一批证据使用指纹缓存，不重复调用模型。
3. 章节写作读取这些记录，但自动抽取结果默认标为“待复核”，不能冒充企业实际数据或直接形成确定性 GO/NO-GO 结论。
4. 公开资料中具备完整且一致输入时，程序可执行公式计算；缺少报价、产能、账期等企业内部数据时保留缺口，不让模型猜数。

页面中的“AI 研究增强”默认折叠，仅用于查看自动整理结果。人工表单和专项测算器通常无需使用；只有补充企业内部数据、真实报价或修正识别结果时才需要展开。自动整理异常只记录日志，不阻断十章行业研究正文生成。
